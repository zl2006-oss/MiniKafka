# miniKafka 需求澄清记录

> 说明：本文件存档需求澄清阶段的逐轮快照，保留当时的原始结论与取舍过程。
> **最终口径以 [`docs/01.需求文档.md`](01.需求文档.md) 第 4 节为准**；历史记录中的结论若被后续评审修订，以文末"评审修订记录"和需求文档为准。

---

## 第 1 轮（2026-11-12）
- 本轮提问：Broker 返回 ack 时，"写入成功"的持久化边界是什么？
- 新增结论：**A1 = 进程级持久化**（页缓存即 ack，kill -9 不丢，掉电可丢最近数据，作为显式能力边界）。"逐条落盘"方案排除。

## 第 2 轮（2026-11-12）
- 本轮提问：同一分区内的消息顺序是否需要严格保证（包括发生超时重试的场景）？
- 新增结论：**A2 = 分区内严格保序**；重试阻塞该分区后续消息；分区之间并行。

## 第 3 轮（2026-11-12）
- 本轮提问：Producer 重试次数/超时耗尽后，客户端应当如何表现？
- 新增结论：**R3 = 有限重试 + 明确失败退出**；至少一次 = 已 ack 消息；重复不去重。

## 第 4 轮（2026-11-12）
- 本轮提问："延迟 P99 < 10ms" 的测量口径（Producer ack 延迟 vs 端到端投递延迟）。
- 新增结论：**R4 = ack 延迟**；端到端仅观测、不设硬目标。

## 第 5 轮（2026-11-12）
- 本轮提问：10 万条/秒的统计口径（单 Producer vs Broker 总入口、是否读写混合）。
- 新增结论：**R5 = Broker 总入口、多 Producer、跨多分区、纯写**。

## 第 6 轮（2026-11-12）
- 本轮提问：Consumer 自动提交的位点定义与推进时机（"已处理" vs "已拉取"）。
- 新增结论：**R6 = 以"已处理"为准**；间隔只影响重复窗口；崩溃不丢消息。

## 第 7 轮（2026-11-12）
- 本轮提问：Broker 重启时对"不完整尾部记录"的恢复策略。
- 新增结论：**R7 = 自动截断尾部**；无人值守恢复；已 ack 消息必可读。
- 后续评审补充：恢复判据明确为记录长度 + CRC，校验通过的记录一律保留（与是否 ack 无关）。

## 第 8 轮（2026-11-12）
- 本轮提问：Consumer 位点提交失败时的行为。
- 新增结论：**R8 = 退避重试 + 告警，不退出**；不丢、最多重复。

## 第 9 轮（2026-11-12）
- 本轮提问：性能验收的硬件基线。
- 新增结论：**R9 = 固定基准机 + 固定脚本 + 固定参数**；具体配置待补。
- 后续评审补充：基准机为虚拟机环境；压测工具用 C++；未达标以实测值如实记录。

## 第 10 轮（2026-11-12）
- 本轮提问：Consumer Group 成员变化时是否要求自动 rebalance。
- 新增结论：**R10 = 全自动 rebalance**；心跳超时触发；验收含分区转移。
- **后续评审修订：R10 降级为 P1（v1.1 可选）；MVP 改为启动时静态分区分配（详见需求文档 R10）。**

## 第 11 轮（2026-11-12）
- 本轮提问：earliest / latest / 指定位点与已提交位点的优先级。
- 新增结论：**R11 = 已提交位点优先**；起始位置仅在无位点时生效；重读需重放或新 group。

## 第 12 轮（2026-11-12）
- 本轮提问："按 offset 重放"是只读回放，还是重置消费组位点？
- 新增结论：**R12 = 只读回放**；无副作用；MVP 不做位点重置。

## 第 13 轮（2026-11-12）
- 本轮提问：Consumer Group 是否支持多 Topic 订阅。
- 新增结论：**R13 = 仅单 Topic**；group 绑定 topic；位点键含 topic 维度。

## 第 14 轮（2026-11-12）
- 本轮提问：Topic 创建后是否允许修改分区数。
- 新增结论：**R14 = 分区数固定**；上限 16 为创建上限；无扩容接口。

## 第 15 轮（2026-11-12）
- 本轮提问：三个角色如何组织为命令行工具。
- 新增结论：**R15 = 单二进制 + 子命令**；源码仍按角色分层。

## 第 16 轮（2026-11-12）
- 本轮提问：磁盘写满时 Broker 的行为（MVP 无保留期清理的必然后果）。
- 新增结论：**R16 = 拒写 + 明确报错**；数据可读；Broker 不崩溃。
- 后续评审补充：ack 前必须主动检查可用磁盘空间，不能仅依赖 `write()` 返回值。

## 第 17 轮（2026-11-12）
- 本轮提问：单条消息大小上限。
- 新增结论：**R17 = 1MB 可配**；超限拒绝，不截断。

## 第 18 轮（2026-11-12）
- 本轮提问：消费者读到分区末尾后的行为。
- 新增结论：**R18 = 默认跟随 + --exit-at-end**。
- 后续评审修订：持续跟随模式下，MVP 按启动时静态分配的分区消费（配合 R10 修订）。

## 第 19 轮（2026-11-12）
- 本轮提问：消息的输入/输出格式。
- 新增结论：**R19 = JSON Lines**；produce 按行读 JSON；consume/replay 逐行 JSON 输出。

## 第 20 轮（2026-11-12）
- 本轮提问：配置通过命令行参数还是配置文件提供。
- 新增结论：**R20 = 命令行参数 + 默认值**；不做配置文件。

## 第 21 轮（2026-11-12）
- 本轮提问：是否补充 Topic 删除与消费者组/位点查询命令。
- 新增结论：**R21 = 均不纳入**；建错分区数换名重建；位点靠行为验收。

## 第 22 轮（2026-11-12）
- 本轮提问：Producer 未指定分区且无 key 时的分区选择策略。
- 新增结论：**R22 = 轮询**；指定分区 > key 哈希 > 轮询。

## 第 23 轮（2026-11-12）
- 本轮提问：批量发送的确认粒度与失败语义。
- 新增结论：**R23 = 逐条返回结果**，只重发失败条目。
- 派生待确认：逐条重试与 R2 保序的冲突（第 24 轮）。

## 第 24 轮（2026-11-12）
- 本轮提问：逐条重试时如何保持分区内严格保序。
- 新增结论：**R24 = 分区级阻塞重试**；其他分区不受影响；R2 保持成立。

## 第 25 轮（2026-11-12）
- 本轮提问：MVP 排除项确认（保留期清理、副本/Raft、ACL、Web）。
- 新增结论：**R25 = 全部排除**；范围封闭。

## 第 26 轮（2026-11-12）
- 本轮提问："100B 消息"的统计口径。
- 新增结论：**R26 = payload 100B + key 8B**，协议头不计入。

## 第 27 轮（2026-11-12）
- 本轮结论：需求澄清结束，无阻塞性问题；剩余仅基准机配置（外部信息）与实现细节（设计阶段）。

## 评审修订记录（2026-11-12）

本轮评审对需求文档的修订（最终口径见需求文档）：

1. R7 补充恢复判据：记录长度字段 + CRC，校验通过的记录一律保留，与是否 ack 无关。
2. 新增 R27：offset 为分区内单调递增逻辑序号，重启时由分段文件尾部扫描重建。
3. 新增 R28：位点文件与消息采用同一可靠性口径，带完整性校验，损坏回退到上一份完整位点。
4. R16 补充：ack 前必须主动检查可用磁盘空间，不能只依赖 `write()` 返回值。
5. 新增"技术与平台约束"：C++11/14、Linux、CMake，禁止 boost/gRPC/现成网络与 MQ 库。
6. R9 补充：基准机为虚拟机环境，配置待补；压测工具用 C++；性能未达标以实测值如实记录。
7. 新增第 8 节验收矩阵，覆盖进程崩溃恢复、位点重启、rebalance 接管（P1）、吞吐、磁盘满、消息超限、批量失败等。
8. **R10 由全自动 rebalance 降级为 P1（v1.1 可选）；MVP 改为启动时静态分区分配。**
9. 新增 R29：批量生产中某分区重试耗尽整体退出前，输出已成功条目的 offset 汇总供对账。
10. "轮次快照"整节移至本文件；第 3 节更名；项目定位固定为演示验证型学习项目；新增术语表与交付物清单。
