### 4.2 P1 边界

- 02：D-03/D-07 只保留 `AssignmentPolicy` 最小边界，无成员表、心跳、会话。
- 03：AD-17 仅接口边界；§4.6 明确 Broker 零成员状态；V3 不计 MVP。
- 04：只持久化位点，不存成员/分配结果。
- 05：报文集合无心跳/join-group/sync-group；§3.6 分配为纯函数。
- 结论：**P1 边界未被扩大**；B6 参数未在 MVP 设计中预设。

### 4.3 依赖禁令

- 语言 C++11/14、仅 Linux、CMake（需求 §6）；03 AD-01 取 C++14，未使用 C++17。
- 无 boost/gRPC/protobuf/现成网络库/MQ 库；CRC、JSON、帧编解码、epoll 自研（03 §2.1/§2.3，05 §2/§10）。
- 压测工具为 `minikafka bench`，C++，链接进单一可执行文件（03 AD-10）。
- 结论：**未违反**。

### 4.4 关键常量与错误覆盖

| 项 | 定稿 | 落点 |
| --- | --- | --- |
| 单条存储记录 | `24 + key_len + value_len ≤ 1 MiB` | 04 §3.5；05 §4.2；CLI 前置校验（R17 口径） |
| 分段 | 默认 256 MiB，下限 2 MiB | 04 §4.3；03 §3.4 `--segment-bytes`（C-6 补充） |
| 磁盘阈值 | 256 MiB | 03 Q-P11；04 §8.3；05 `disk_full` |
| 索引 | 4 KiB 稀疏、派生数据 | 04 §4.4 |
| 帧/批量 | 8 MiB / 1024 条 / 4 MiB 或 500 条 | 05 §8 |

**04 边界用例 → 05 错误码**：空分段/半条/CRC 损坏 → 启动恢复，不产生协议错误；基址断链/封存损坏 → `storage_unavailable`；元数据损坏/缺失 → `topic_not_found`；单条超限 → `message_too_large`；磁盘满 → `disk_full`；残留 `.tmp` → 启动忽略；offset 越界 → `offset_out_of_range`。**无缺口**。

## 7. 终审建议清单（8 条）

1. **D-04-1/2/6**：封存段损坏与基址断链仅降级该分区、不修改文件、不做 Topic 级降级；Broker 继续服务健康分区。
2. **D-04-3**：`--verify-storage` 不进入 Broker CLI，仅作为独立测试开关/编译期选项。
3. **C-6 / 03 v1.1 补充**：broker CLI 增加 `--segment-bytes`（默认 268435456，下限 2097152）；这是 storage-rules S-03 已确认要求，03 B4 原表遗漏。
4. **OffsetFetch 合并静态分配**：一次请求返回“分配分区 + 已提交位点”，替代 03 §5.2 图示的两次往返；无成员状态，语义不变。
5. **跟随策略**：客户端 100ms 轮询 + Broker 空响应，不实现 Broker 侧长轮询/等待队列。
6. **协议上限**：单帧 8 MiB、Produce ≤1024 条、Fetch/Replay 单响应 ≤4 MiB 或 500 条；客户端按 512 条/4 MiB 组批。
7. **错误码与退出码**：`disk_full` 在 Produce 重试耗尽为 4、在 topic create 为 3；`invalid_*` 为 3，纯用法错误为 2；`storage_unavailable` 为 3。
8. **04 补充规则**：首段 base 必须为 0；损坏 Topic 目录禁止同名覆盖；位点提交不回退（max）。
