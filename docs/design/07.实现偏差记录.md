## D-01 分段文件名解析要求严格 24 字符

- **涉及**：M4d 恢复扫描（`src/storage/recovery.cpp`）。
- **设计原文**：04 §5.2 "枚举 `<base_offset:020d>.log`"。
- **实现**：文件名必须是 20 位十进制 + `.log` 共 24 字符，其余（含 `0001.log`、`*.tmp`）一律忽略。
- **理由**：避免 `1.log` 与 `00000000000000000001.log` 被当成两个分段。
- **影响**：无（设计口径即 20 位补零）。**不需要裁决。**

## D-02 `broker` 默认数据目录取 `./data`

- **涉及**：M5b `src/main.cpp`、`BrokerConfig::data_dir`。
- **设计原文**：`prototype/CLI交互规范.md` §2.1 写 `--data-dir` 默认 `.demo-state`；04 存储设计默认数据目录为 `./data`。
- **实现**：默认 `./data`（`common::kDefaultDataDir`）。
- **理由**：`.demo-state` 是原型演示目录，M4 的目录布局与 04 对齐，真实服务用 `./data`。
- **影响**：验收脚本若按原型期望 `.demo-state`，需显式传 `--data-dir`。**待裁决：是否改回 `.demo-state` 或同步更新原型文档。**

## D-03 告警事件形状统一为 `{"event":"warning","detail":...}`

- **涉及**：M5b `Broker::EmitWarning`、启动期 warnings 输出。
- **设计原文**：原型 §2.1 的 stderr 事件为 `{"event":"recovery","topic":"...","partition":0,"kept":5,"dropped":1}`（结构化字段）。
- **实现**：统一输出 `{"event":"warning","detail":"<自由文本>"}`，每条 warning 一行。
- **理由**：M4 恢复与 M6 位点降级的告警来源多样（基址断链、封存段损坏、位点双槽损坏），字段集合不同；先统一为文本，待结构化需求明确后再细分。
- **影响**：脚本若要解析 `kept/dropped` 需新增字段。**待裁决：是否在 M7 阶段拆回结构化事件。**

## D-04 Storage Worker 队列满时按超时回错误，而非暂停连接读取

- **涉及**：M5b `Broker::TaskQueue::Push`、`BrokerConfig::queue_push_timeout_ms`。
- **设计原文**：03 §4.3 "Storage Worker 队列设高/低水位；高水位时暂停相关连接读取，避免无界内存增长"。
- **实现**：保留高/低水位（默认 4096/1024）。满时投递方最多等待 200 ms，仍未降到低水位则本次请求直接回 `broker_unavailable`（客户端按 R3 重试）。
- **理由**：暂停读取需要 M3 暴露 `PauseRead(ConnectionId)` 这类接口，当前 `Connection`/`ReactorPool` 未提供；而让 IO 线程在 `Push` 上无限阻塞会与"worker 向 IO 队列 `Send` 满时阻塞"形成环形等待（死锁）。超时回错误是当前结构下不破坏正确性的方案。
- **影响**：极端拥塞下客户端会看到 `broker_unavailable` 而不是"变慢"。**待裁决：是否为 M3 增加暂停读取接口以回归设计口径。**

## D-05 分区亲和键的具体函数

- **涉及**：M5a `broker::PartitionKeyFor`。
- **设计原文**：AD-05 只要求"同一分区恒定归一个 worker"，未指定映射函数。
- **实现**：`key = Fnv1a32(topic) ^ (partition * 0x9E3779B9u + 0x7F4A7C15u)`，`worker = key % M`。
- **理由**：只用 `partition % M` 会让所有 Topic 的 0 号分区压到同一个 worker；加入 topic 散列后可分散。
- **影响**：worker 分配不同但语义不变（同分区恒定同 worker）。**不需要裁决。**

## D-06 Topic 表用写时复制快照实现无锁读

- **涉及**：M5a `PartitionManager`。
- **设计原文**：03 §5 要求"已提交位点/分区句柄单线程独占"，并强调热路径不加锁；未规定 Topic 表的同步方式。
- **实现**：`std::shared_ptr<const std::map<...>>` + `std::atomic_load/store`，Create 时复制发布；读路径无锁。创建操作由 `Broker` 的一把互斥量串行化。
- **理由**：分区数创建后不可变（F-T03），适合快照发布。
- **影响**：无。**不需要裁决。**

## D-07 测试专用同步入口 `Broker::DispatchSync`

- **涉及**：M5b `Broker::DispatchSync`。
- **设计原文**：无对应设计条目。
- **实现**：把一次请求走同一条 `Dispatch` 路径，但响应收进本地缓冲并同步等待（5 s 超时）。
- **理由**：给分发/错误路径做确定性单测，不引入第二套分发逻辑。当前生产路径（socket）未使用它。
- **影响**：多一个公开方法。**待裁决：是否在 M7 后移除或改为 `private` + friend 测试。**

## D-08 `Socket::Bind` 失败信息补 `strerror(errno)`

- **涉及**：M3 `src/net/socket.cpp`。
- **设计原文**：05 §5 错误码不变（仍为 `internal_error`）。
- **实现**：message 由 `"bind() failed"` 改为 `"bind() failed: <strerror>"`。
- **理由**：端口占用时只看到一句话无法定位。错误码未变，不影响协议。
- **影响**：仅日志文案。**不需要裁决。**

## D-09 group 分片键取 `Fnv1a32(group)`

- **涉及**：M6 `Broker::GroupWorkerIndex`。
- **设计原文**：03 §4.3 "`hash(group) % M` 选择 Storage Worker"，未指定散列算法。
- **实现**：复用 M1 的 `common::Fnv1a32(group)`（与 B1/Q-P5 的 key 散列同一函数）。
- **理由**：跨进程/跨版本稳定，避免引入第二种散列。
- **影响**：无。**不需要裁决。**

## D-10 `--from latest` 与起始位点裁决靠一次越界 Fetch 探测 `log_end`

- **涉及**：M7 `src/client/consumer.cpp`、`src/client/replay.cpp`。
- **设计原文**：R11 要求"无已提交位点时按 `--from` 选择 earliest/latest/指定位点"，02 §3.6 又说"读取路径返回分区日志末尾 offset（支撑 latest）"；但 05 的 7 种报文里没有独立的"查询 log_end"请求。
- **实现**：发一次 `FetchRequest{offset = 2^64-1}`，Broker 回 `offset_out_of_range`，响应体中仍带 `log_end_offset`（05 §3.5 该字段总是编码），据此得到分区末尾。
- **理由**：不新增报文类型（"未列出的参数/报文不得擅自增加"），把探测压在做一次正常读的代价上；只读、不改任何状态。
- **影响**：`latest` 与"指定位点超界收敛"各多一次 RTT（仅启动期、每分区一次）。**待裁决：是否愿意为 M7 增加一种元数据查询报文以去掉这次探测。**

## D-11 消费中遇到 `offset_out_of_range` 时收敛到 `log_end` 并告警

- **涉及**：M7 `src/client/consumer.cpp`。
- **设计原文**：R11/R28 规定已提交位点优先、损坏位点回退上一份完整位点，但未规定"已提交位点大于分区日志末尾"（日志被截断/数据目录被替换）时怎么办。
- **实现**：收到 `offset_out_of_range` 时把该分区起点收敛到响应中的 `log_end_offset`，向 stderr 输出一条 `{"event":"offset_reset",...,"reason":"offset_out_of_range"}`，并把它作为待提交位点。
- **理由**：R8 要求"消费者不主动退出"；若在这里退出，运维只能手工改数据目录。收敛后至少消费者可继续工作，且丢失区间有明确告警。
- **影响**：极端场景下会跳过一段不可读的区间（该区间已不存在，实际无消息可丢）。**待裁决：是否改为"直接退出并要人工介入"或"按 `--from` 重新裁决"。**

## D-12 `--consumer-count` 上限 16、`--auto-commit-interval` 上限 86400s

- **涉及**：M7 `src/client/consumer.cpp`、`src/client/cli.cpp`。
- **设计原文**：03 §3.4 只规定 `0 ≤ i < n`，未给 `n` 与提交间隔的取值上界。
- **实现**：`n ∈ [1,16]`（与 M6 `kMaxConsumerCount` 对齐，客户端先拒，避免把一定失败的请求发给 Broker）；提交间隔 `∈ [1s, 86400s]`，非正数/非数字回 `invalid_interval`（退出码 2）。
- **理由**：M6 的分配器只保证 16 个槽位内的性质验证；提交间隔下界避免 0 值导致每次循环都提交。
- **影响**：超出范围直接退出码 2，错误信息明确。**不需要裁决（与 M6 实现边界一致）。**

## D-13 `bench` 用显式分区轮转取并发，`--mode latency` 固定 `batch=1`

- **涉及**：M8 `src/bench/bench.cpp`。
- **设计原文**：R26 只固定负载（payload 100B + key 8B）与"多 Producer 并发、跨多分区、纯写"；未规定压测客户端如何选分区、延迟模式如何组批。
- **实现**：每个 Producer 线程按 `(producer_index + 轮次) % partition_count` 显式指定分区（跨分区并行，避免单分区串行成为瓶颈）；`--mode latency` 强制 `batch=1`，以"一次请求一条"测 send→ack。
- **理由**：若按 key 哈希选分区，所有线程会撞到同一分区，压出来的是单分区串行上限，与 R5"Broker 总入口吞吐"口径不符。
- **影响**：压测不覆盖 key 哈希路径（该路径由 `produce` 与单元测试覆盖）。**不需要裁决。**

## D-14 `--log-level` 只做取值校验，暂不影响输出级别

- **涉及**：M5b `src/main.cpp`。
- **设计原文**：03 §3.4 列出 `--log-level warn`（默认 warn）。
- **实现**：接受 `warn|info|debug`，非法值退出码 2；当前实现无分级日志器，生命周期事件与告警始终输出（均为 warn 级别语义）。
- **理由**：不引入只为参数存在的日志框架；`info/debug` 档位留待需要时再补。
- **影响**：`--log-level info/debug` 目前不改变输出。**不需要裁决（若要求生效则属于新增功能）。**
